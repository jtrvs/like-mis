# Обновление импорта выписок

Основа обновления — итоговая версия интерфейса `63b706b`, которая уже проверена в Docker у Стаса. Изменений схемы базы, миграций и зависимостей нет.

## Обновление распакованного проекта на Windows

1. Сохраните резервные копии папок `web` и `e2e` вне папки проекта. Не копируйте и не удаляйте тома Docker.
2. Распакуйте архив обновления. Откройте папку `files` внутри архива.
3. Скопируйте папки `web`, `e2e` и `docs` из `files` в корень проекта, где находятся manage.py и docker-compose.yml. Подтвердите замену одноимённых файлов. Существующие папки не удаляйте: нужно объединение содержимого, а не замена всей папки web пустой версией.
4. В PowerShell из корня проекта:

```powershell
docker compose up -d --build
docker compose exec web python manage.py test
```

Ожидается `Ran 88 tests` и `OK`. Если есть ошибка, сохраните последние строки вывода. Не запускайте seed_demo повторно: существующие пациенты и записи сохраняются. Не используйте down -v.

## Ручная проверка

Войти под petrova, открыть тестового пациента и «Загрузить выписку». На шаге сверки заполнить даты только у тех препаратов, которые действительно нужно перенести. Не переносить выписку от другого пациента. При неизвестных датах снять отметку с препарата. Проверить один перенос, затем повторить тот же документ с теми же датами: повторного назначения быть не должно.

Если действующее назначение имеет другую схему или дату начала, импорт покажет ошибку и ничего из этой попытки не сохранит. Сверьте исходные документы, а не меняйте даты только ради прохождения формы.

Шкалы из выписки пока показываются для сверки. Уже созданные дубликаты требуют отдельной проверки врачом и автоматически не удаляются. Даты начала и отмены подтверждает врач; автоматического извлечения дат нет.

## Передача коллеге через Git

Ветка в bundle: stas/import-dates-fix. Она включает весь предыдущий интерфейс и исправление импорта. В существующем репозитории с сохранёнными текущими изменениями:

```bash
git fetch ПУТЬ/К/lambda-import-fix.bundle stas/import-dates-fix:stas/import-dates-fix
git switch stas/import-dates-fix
```

Если локальная ветка с таким именем уже есть, используйте другое свободное имя после двоеточия. Ветка на GitHub автоматически не отправляется. Перед объединением проверьте новые изменения коллег.
