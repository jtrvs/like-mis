# Обновление интерфейса — первый блок

Основа: ветка `stas/ui-prototype`, коммит `6f90849973c80d5be3aaf825405aaf55948aebdf`.
Рабочая ветка: `stas/ui-refresh`.

## Что изменилось

- Общая палитра: белые поверхности, сиреневый основной цвет и мятные акценты.
- Локальный шрифт Golos Text сохранён; добавлены SVG-значки без внешних сервисов.
- Обновлены вход, список пациентов и главная страница пациента «Сегодня».
- Поиск по имени и основному диагнозу, фильтры по существующим категориям и по подключению пациента.
- Поиск ограничен пациентами, уже доступными этому врачу. Сигналы остаются видимыми при поиске.
- Вместо «Стабильно» выводится «Нет открытых сигналов», а для пустой истории — «Нет записей».
- Нулевой балл шкалы отображается числом, отсутствие результата — прочерком.
- Общая навигация, состояния фокуса и размеры элементов адаптированы к телефону.
- Обновлены значок, цвет темы PWA и версия кеша статических файлов.

Расчёт шкал, правила алертинга, проверка препаратов и подтверждение врачебных решений не менялись.
Миграций и новых зависимостей нет. Подробная карточка пациента использует общие стили, её структура будет дорабатываться следующим блоком.

## Применение патча

В репозитории должна быть исходная UI-ветка. Сначала сохраните свои незакоммиченные изменения.
Команды выполняются из корня репозитория; путь к патчу замените на свой:

```bash
git switch stas/ui-prototype
git switch -c stas/ui-refresh
git apply --check /path/to/ui-refresh-block1.patch
git apply /path/to/ui-refresh-block1.patch
docker compose up --build
```

Если `git apply --check` сообщает об ошибке, сначала сверьте исходную версию. Не применяйте патч с принудительным игнорированием ошибок.

Для отдельной демонстрационной базы данные можно создать командой:

```bash
docker compose exec web python manage.py seed_demo
```

Не запускайте повторное создание демонстрационных данных без необходимости. Команда `seed_demo --reset` удаляет существующие записи и предназначена только для одноразовой тестовой базы.

## Второй этап: карточка пациента

Сигналы вынесены над двумя колонками. Вверху появились ссылки на разделы; на телефоне они позволяют перейти к лечению, графикам и сообщениям без длинной прокрутки. Диагноз показывается целиком. Клинические действия, причины предупреждений, источники и подтверждение врачом сохранены.

Последние PHQ-9 и GAD-7 показаны отдельно, с датами и диапазонами. Убрана общая цветная разметка тяжести для двух разных шкал. Графики используют полные даты и время; записи разных шкал упорядочиваются совместно. При отсутствии данных показано объяснение вместо пустого графика. Ноль часов сна отображается как ноль.

Проверки второго этапа: 71 тест Django; все 9 существующих браузерных сценариев; 16 проверок карточек при ширине 320, 390, 768 и 1440 пикселей. Проверены срочный сигнал, обычное наблюдение, противопоказания и карточка без дневника. Ошибок JavaScript и горизонтального переполнения не обнаружено. Дополнительно повторены 15 проверок стартовых экранов. Окружение проверки — SQLite, Python 3.12; Docker и PostgreSQL здесь не проверялись.

## Третий этап: дневник и опросники

Обязательные настроение и тревога отделены от дополнительных вопросов. Вопросы сгруппированы в карточки, добавлены пояснения диапазонов и счётчик ответов. Счётчик работает в браузере без отправки данных; при отключённом JavaScript формы по-прежнему отправляются обычным способом. Черновики не сохраняются в браузерное хранилище.

При ошибке дневника показаны конкретные поля, а введённые значения сохраняются в повторно показанной форме. Частично заполненный опросник также сохраняет выбранные ответы после серверной ошибки. Формулировки шкал, допустимые значения, расчёт баллов и обработка кризисных ответов не менялись. Исправлено перекрытие кнопок 0–10 невидимыми радиопереключателями.

Проверки: 73 теста Django, включая повторное отображение ошибочных форм; 9 браузерных сценариев; 12 проверок дневника, GAD-7 и PHQ-9 при ширине 320, 390, 768 и 1440 пикселей. Проверены нажатия и счётчики ответов, отсутствие ошибок JavaScript и горизонтального переполнения. Окружение проверки остаётся локальным, с SQLite; Docker/PostgreSQL здесь не запускались.

## Четвёртый этап: лекарства, переписка, помощь

На странице лекарств сначала показаны сегодняшние приёмы, затем назначения врача и сводка отметок. История за предыдущие шесть дней свёрнута, ближайшие приёмы следующих дней выделены отдельно. Дозы, расписание и правила отметки не менялись. Сводка обновляется при открытии страницы, что явно указано рядом с ней.

В переписке показаны ведущий врач, автор и дата каждого сообщения. После отправки выводится подтверждение. Если ведущего врача нет, поле отправки скрыто; прямой POST также сообщает, что отправки не произошло. Убрано обещание ответа в рабочее время, так как график врача системе неизвестен.

На экране помощи первым показан экстренный вызов, далее — разрешённые пациентом контакты. Ошибки добавления контакта теперь видны, форма остаётся открытой с введёнными значениями. В кризисном состоянии экран больше не утверждает, что врач получил сообщение и уже связывается с пациентом: подтверждения доставки и прочтения здесь нет. Исходный справочник линий помощи сохранён; актуальность его номеров и режимов работы в этом UI-этапе не проверялась.

Проверки: 77 тестов Django, 9 существующих браузерных сценариев. Лекарства, переписка, обычный и кризисный экран помощи проверены при ширине 320, 390, 768 и 1440 пикселей. Дополнительно проверены отправка сообщения через браузер и сохранение отметки приёма после перезагрузки. Окружение — SQLite и Python 3.12, без проверки Docker/PostgreSQL и реальных внешних каналов доставки.

## Пятый этап: динамика пациента и загрузка выписки

В динамике показаны последние баллы с датами, диапазоны PHQ-9/GAD-7 и явные состояния отсутствия данных. Графики используют тот же компонент, что и карточка врача: полные даты и время, совместная сортировка записей, сиреневый и мятный цвета. Последние пять записей дневника доступны текстом. Период графика шкал — 90 дней, дневника — до 30 последних записей. Последний результат шкалы показывается даже вне периода графика, с его фактической датой.

Импорт разделён на вставку текста, сверку и подтверждение переноса. На сверке рядом доступен исходный текст, включая прокрутку с клавиатуры. Ошибки пустой формы показываются явно. Неполные назначения остаются недоступными для переноса; шкалы отмечены как сведения только для сверки. Добавлены пояснения к существующему поведению сервера: даты назначения и отмены записываются сегодняшним числом. Извлечение, запись данных и клинические правила не менялись.

Ограничение исходного сервера, которое следует обсудить с владельцем импорта: исторические даты препаратов не сохраняются, а шкалы из текста не пополняют историю ответов. Повторный импорт того же препарата также может создавать отдельные назначения. Эти ограничения не исправлялись в рамках оформления.

Проверки: 80 тестов Django, 9 браузерных сценариев; динамика и оба шага импорта проверены на ширинах 320, 390, 768 и 1440. Добавлены проверки нулевых результатов, отсутствия истории, ошибки пустой выписки, безопасного отображения исходного текста и отсутствия записи в карточку до подтверждения. После подтверждения переносятся только отмеченные сведения. В браузерном сценарии ожидание старого заголовка заменено ожиданием области сверки. Условия локальной проверки прежние: SQLite, Python 3.12, без Docker/PostgreSQL.

## Финальная сборка и оставшиеся проверки

Удалённые ветки проверены 23 октября 2026 года: `main` — `86bd4bd`, роль 4 — `dea9376`. Интерфейс основан на `stas/ui-prototype` (`6f90849`) из предоставленного bundle и включает более поздние исправления роли 4 (`b0c9a1f`). В итоговую локальную ветку включена история доступной `origin/main`; выкладки на GitHub не выполнялось.

Исправлены два дефекта запуска: закрыт JSON-список CMD в Dockerfile, для сервиса web подключён `.env`, из которого Django читает DB_NAME/DB_USER/DB_PASSWORD. Добавлены PNG-иконки PWA 192×192 и 512×512. Service worker кэширует только общие статические файлы: офлайн-страницу, CSS и иконки. Карточки, сообщения и ответы пациентов не кэшируются. При недоступности сервера показывается офлайн-страница со статусом 503; недоступность сети не выдаётся за успешное сохранение.

Повторно прошли 80 тестов Django. В Chromium проверены загрузка манифеста и иконок, содержимое кэша, навигация при отключённом тестовом сервере, применение сохранённых стилей и восстановление страницы после возврата сервера. Синтаксис CMD проверен JSON-парсером, compose — YAML-парсером. Это не заменяет запуск контейнеров: Docker в среде проверки отсутствует. Установка PWA на физический телефон также не выполнялась; для установки с телефона на удалённый сервер потребуется HTTPS.

Перед показом команде: запустить Docker/PostgreSQL, проверить вход врача и пациента, повторить тесты, установить PWA на реальный телефон. Клинические ограничения импорта и актуальность справочника линий помощи остаются на согласовании с владельцами соответствующих модулей.
