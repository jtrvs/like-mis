# Запуск итогового интерфейса

Эта ветка содержит весь проект с интерфейсом и изменениями пяти этапов. Применять промежуточные патчи к ней не нужно. Не переносите весь архив поверх рабочей папки коллег: сначала проверьте отдельную копию.

## Отдельная проверочная копия

Распакуйте полный ZIP, откройте терминал в папке с `manage.py`, `Dockerfile` и `docker-compose.yml`. Для команд ниже Docker уже должен быть установлен и запущен.

В новой папке, если файла `.env` ещё нет:

```bash
cp .env.example .env
```

Файл содержит демонстрационные настройки. Для публичного сервера нужен собственный секретный ключ и настройки доступа; не загружайте `.env` в Git.

```bash
docker compose up --build -d
docker compose ps
docker compose exec web python manage.py test
```

Дождитесь запуска web. На новой, отдельной тестовой базе создайте синтетические записи:

```bash
docker compose exec web python manage.py seed_demo
```

Не используйте `seed_demo --reset` на рабочей базе: он удаляет существующие данные. Если уже имеются данные команды, пропустите создание демонстрационных записей.

Открыть: http://localhost:8000/login/

Демонстрационный вход: `sidorov` — терапевт, `petrova` — психиатр, `anna` — пациент. Пароль: `Demo-2026!`. Они появятся после seed_demo и предназначены только для демонстрационной среды.

Если есть ошибка:

```bash
docker compose logs --tail=100 web db alerts-worker
```

Не удаляйте Docker volumes и не запускайте `docker compose down -v`: для этой проверки это не требуется. Если порт 8000 занят другой копией приложения, сначала определите, какая копия работает; не останавливайте чужой сервис вслепую.

## Проверка функций

- Пациент: дневник, PHQ-9/GAD-7, отметка приёма, сообщение врачу, динамика.
- Врач: список и поиск пациентов, карточка, просмотр сигналов, направление, подтверждение назначения.
- Выписка: до подтверждения данные не переносятся; исходный текст виден рядом.
- Помощь: контакты и ошибки их добавления, понятный доступ к экстренному вызову.
- Телефон/PWA: проверить на реальном устройстве. Для удалённого адреса нужен HTTPS. Проверка в настольном Chromium не подтверждает установку на Android или iOS.

## Перенос через Git-bundle

Альтернатива ZIP — открыть ветку из bundle в отдельной папке:

```bash
git clone -b stas/ui-refresh ПУТЬ/К/lambda-ui-final.bundle like-mis-ui-final
```

Для переноса в существующий репозиторий команды, сохраняя историю:

```bash
git fetch ПУТЬ/К/lambda-ui-final.bundle stas/ui-refresh:stas/ui-refresh-ready
git switch stas/ui-refresh-ready
```

Имя `stas/ui-refresh-ready` должно быть свободным. Сначала сохраните незавершённые изменения в существующем репозитории. Команды сами ничего не отправляют на GitHub. В итоговую ветку включена доступная main (`86bd4bd`); перед последующим слиянием нужно проверить, не появились ли новые коммиты команды.

## Что уже проверено

80 тестов Django, 9 сквозных браузерных сценариев и проверки размеров экранов. Манифест, PNG-иконки, офлайн-заглушка, стили и восстановление сети проверены в Chromium. Локальные проверки выполнены с SQLite и Python 3.12.

Docker/PostgreSQL и установка на физический телефон здесь не проверялись. CMD Dockerfile и YAML compose проверены парсерами. Ограничения импорта и справочника помощи описаны в `docs/ui-refresh.md`.
